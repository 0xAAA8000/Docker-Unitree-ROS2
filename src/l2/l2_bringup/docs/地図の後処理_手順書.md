# 地図の後処理 手順書(ほうき星の除去・ループ補正・外れ点除去)

`l2map -s` で作った地図(`~/maps/l2_日時.pcd`)を、自己位置推定に使える状態に整える手順。
ツールはすべて `~/ros2_ws/tools/` にある(このリポジトリでは `src/l2/l2_bringup/tools/`。
以下の `~/ros2_ws/tools/` は読み替える)。`pcd_sor.sh` には CloudCompare(snap 版)が必要。

## 0. 前提
- **ほうき星**: 地図作成中に Point-LIO の推定が破綻し、点が数百 m〜数 km 先まで尾を引いて飛んだ部分。
  USB-LAN アダプタが切れてデータが数秒途切れると起きやすい(2026-10-06 の地図はこれが原因)。
- Point-LIO は点を**取り込んだ順**に保存するので、ファイル内の位置 ≒ 時刻。以下のツールはこれを利用する。
  **順番が変わる処理(CloudCompare での編集・間引きなど)は最後に回す。**
- 元の地図は上書きしない(すべて別名で保存する)。

## 推奨の流れ
```
元の地図 ──① ほうき星の除去──▶ _trim ──②(任意)ループ補正──▶ _loop ──③ 外れ点除去──▶ _clean
```
② は判定で「使わない」と出たら飛ばし、`_trim` に ③ をかける。

```bash
cd ~/maps
python3 ~/ros2_ws/tools/pcd_trim.py    l2_日時.pcd -o l2_日時_trim.pcd          # ①
python3 ~/ros2_ws/tools/pcd_loopfix.py l2_日時_trim.pcd -o l2_日時_loop.pcd     # ②(任意)
~/ros2_ws/tools/pcd_sor.sh             l2_日時_trim.pcd l2_日時_clean.pcd       # ③(② を使うなら _loop を入力に)
```

## ① ほうき星の除去(`pcd_trim.py`)
```bash
python3 ~/ros2_ws/tools/pcd_trim.py l2_日時.pcd                      # 確認だけ(書き出さない)
python3 ~/ros2_ws/tools/pcd_trim.py l2_日時.pcd -o l2_日時_trim.pcd  # 書き出す
```
- ファイルを 0.1% ずつの区間に分け、区間の中心が **1%(10 分の地図なら約 6 秒)で 25 m 以上**動き、
  戻ってこない所を破綻とみなして、その 1% 手前で切る。
- 出力の見方:
  - `divergence detected at 96.8%` … 破綻を検出した位置
  - `cut at 95.6%` … ここまでを残す
  - `kept ... extent` … 残した範囲。歩いた場所として妥当な大きさか確認する(数百 m 以上なら残っている)
  - `no divergence found` … 破綻なし(そのまま ③ へ)
- 自動判定がおかしいとき: `--cut 96.5` で切る位置(%)を指定する。`--jump 15` で判定を厳しくする。
- 注意: 破綻より後の部分(切った残り)は捨てることになる。途中で破綻した地図は、前半しか残らない。

## ② ループ補正(任意・近似)(`pcd_loopfix.py`)
一周して出発地点に戻ったのに、高さなどがずれている場合に試す。
```bash
python3 ~/ros2_ws/tools/pcd_loopfix.py l2_日時_trim.pcd -o l2_日時_loop.pcd
```
- 地図の最初の部分(`--start 0:10`、%)と最後の部分(`--end 93:100`)を重ね合わせてずれを求め、
  そのずれを時間に比例して地図全体に配る。約 4 分。
- **最後の `RESULT:` を必ず見る**:
  - `LESS consistent ... Do not use it` → **使わない**。補正で同じ物が二重になった(ずれが一定の割合で
    たまったのではなく、途中で一気に起きたため)。`_trim` を ③ に回す。
  - `consistency did not get worse` → CloudCompare で見て問題なければ使う。
- `WARNING: the end does not clearly match the start` → 最初と最後が同じ場所を写していない。
  `--end` の範囲を変えるか、補正をあきらめる。
- 限界: 軌跡と元のスキャンがない状態での近似。確実に直すには記録(`-r`)から作り直す(「根本対策」参照)。

## ③ 外れ点除去(`pcd_sor.sh`、CloudCompare)
```bash
~/ros2_ws/tools/pcd_sor.sh l2_日時_trim.pcd l2_日時_clean.pcd          # 近傍 6 点・1.0σ
~/ros2_ws/tools/pcd_sor.sh l2_日時_trim.pcd l2_日時_clean.pcd 10 2.0   # 弱めにかける例
```
- CloudCompare の SOR フィルタ(各点の近傍点までの平均距離が、全体の平均 + σ×標準偏差より大きい点を除く)。
  1000 万点で十数秒。
- CloudCompare の出力は他のツールで読めない形式(詰め物の欄 `_`)なので、自動で x y z intensity に書き直す。
- 消えすぎるとき(遠くの壁や木がまばらになる)は σ を大きくする(1.0 → 2.0)。
- CloudCompare を手で使う場合の注意(snap 版):
  - `/tmp` に保存すると snap 専用の場所に入って見えない → `~/maps` などに保存する
  - コマンドライン実行では `-AUTO_SAVE OFF` を付ける(付けないと処理ごとに途中結果が保存される)

## 結果の確認
```bash
pcl_viewer l2_日時_clean.pcd                 # (RTX で表示)
cloudcompare l2_日時.pcd l2_日時_clean.pcd   # 前後を重ねて比べる
```
- 上から見て: 歩いた場所の形になっているか、遠くへ伸びる線(ほうき星)が残っていないか
- 横から見て: 地面や屋根が二重になっていないか、傾いていないか

## 自己位置推定で使う
```bash
l2loc ~/maps/l2_日時_clean.pcd -a
```
`l2loc` は地図を指定しないと `~/maps` の一番新しい `l2_*.pcd` を使う。試しに作ったファイルは
`~/maps/experimental/` などに移しておく。

## 根本対策(ほうき星・ずれを作らない)
1. USB-LAN アダプタは **PC 本体のポートに直接** 挿す(ハブ経由で切れていた)。
2. 地図作成は必ず **`l2map -s -r`**(生データを記録)。記録があれば:
   - 破綻した原因(データの途切れなど)を調べられる
   - ループを閉じて全体を補正する地図作成方法を、後からかけ直せる(屋外で一周する地図向け。導入は今後)
3. 屋外で一周するときは、出発地点の床に印を付け、最後にそこへ戻ってから止める。

## 実例(2026-10-06 の地図 `l2_20261006_173651.pcd`、建物の周りを約 11 分)
| 段階 | 結果 |
| --- | --- |
| ① ほうき星の除去 | 96.8% で破綻を検出 → 95.6% で切る。1,195 万 → 1,143 万点 |
| ② ループ補正 | 最後の部分が高さ −6.4 m・向き −6.3° ずれていた。補正すると占有ボクセル +20.8% → **使わない** |
| ③ 外れ点除去 | 1,143 万 → 1,031 万点(9.8% 除去) |
